# 编排模式语言

让多 agent 工作流值回成本的重复出现的模式，按它们买到的东西组织。每个模式给出：何时适用、何时不适用、支撑它的不变式。模式是词汇表不是菜单——任务需要时发明新形状，并给每个屏障写辩护注释。

> 本文件改编自 hesreallyhim/ultracode-workflows 的 `patterns.md`（MIT），按 dsh 0.2.0-rc.2 能力适配：删除 token 预算钩子、`workflow()` 嵌套与 worktree 隔离（dsh 无此能力），替换为轮次上限与分片不相交规则。

## 结构模式——工作怎么流

### Pipeline 默认

`pipeline(items, stage1, stage2, …)` 让每条目**独立**走完全程：条目 A 可以在验证阶段时条目 B 还在评审。墙钟成本是最慢单条目*链*，不是各阶段最慢项之和。

只要下游阶段只需要自己条目的上游结果——绝大多数时候如此——就用它。文档审计让每份文档流过 extract → check → fix，零屏障：修 README 不取决于部署指南的检查结果。

pipeline 阶段内用 `{phase: '...'}` 选项分组，**不要**用全局 `phase()`：并发条目会竞争全局状态。

```js
const results = await pipeline(
  docs,
  (doc) => agent(extractPrompt(doc), { phase: 'Extract', schema: CLAIMS }),
  (claims, doc) => agent(checkPrompt(doc, claims), { phase: 'Check', schema: CHECKED }),
)
```

### 屏障要辩护

`parallel(thunks)` 等所有东西；空等是真实成本，所以每个屏障都要写得出辩护：第 N 阶段必须**真的**需要第 N−1 阶段的全部输出。合法情形只有四类：

- **去重先于昂贵工作**——五个评审维度常报同一个缺陷，验证前按 `(file, 行桶)` 合并，每个重复省一个验证 agent。
- **跨条目聚合驱动下一步决策**——loop-until-dry 的轮计数需要整轮产出；多模态扫查的佐证排名需要全部模态合并。
- **评审者/合成者需要全场**——评审团给所有提案打分；地图合成者画跨子系统依赖图。
- **两个分析的 join**——升级计划字面上是（改了什么）×（我们在用什么），单边无用。

如果你的"屏障"后面跟着 flatten/map/filter 再扇出——那不是屏障，是穿着屏障外衣的 pipeline 阶段。

### Loop-until-dry（未知总体的发现）

对总体规模未知的问题（bug、死代码、不稳定测试），固定扇出漏尾巴，固定计数任意停。持续开轮直到**连续 K 轮没有新发现**，配硬轮次上限兜底。两个不变式保证收敛：

1. **对 `seen` 去重，绝不对 `confirmed` 去重**——被驳回的发现再出现时不该每轮重试：

```js
const seen = new Set(); let dry = 0, round = 0
while (dry < 2 && round < MAX_ROUNDS) {           // 硬上限是唯一兜底（dsh 无预算钩子）
  const found = (await parallel(lensesFor(round).map(l => () =>
    agent(huntPrompt(l), { phase: 'Hunt', schema: BUGS })))).filter(Boolean).flatMap(r => r.bugs)
  const fresh = found.filter(b => !seen.has(key(b)))
  fresh.forEach(b => seen.add(key(b)))
  if (!fresh.length) { dry++; round++; continue }
  dry = 0 /* …验证 fresh、累积 confirmed… */; round++
}
```

2. **每轮轮换搜索策略**——按轮号切片视角池（确定性；dsh 虽不禁用随机，但确定性让复现与推理更稳）。否则第 2 轮重找第 1 轮的发现，循环要么秒干、要么永不干。

### 波次与提前中止

条目按批处理时，一批**全员失败**本身是信息：指令错了，不是条目错了。迁移文件按 ~8 个一波，整波全部被阻塞就中止余下波次——第 8 个文件学到比第 80 个好。

### 有界修复循环与诚实出口

验证 → 按根因聚类失败 → 不相交簇并行修复 → 再验证，至多 N 轮。不收敛时返回 `status: 'unstable'` 与存活失败。**上限是特性**：三轮不收敛的工作需要人来决策，假装能收敛只是烧 token 掩盖事实。

## 信任模式——结果怎么赢得相信

### 对抗验证

发现者的输出是*主张*。到达用户之前要过独立怀疑者一关，其明确职责是**反驳**它——找发现者漏掉的守卫、让输入不可能的调用方、已经覆盖它的测试——并被要求"不确定时默认反驳"。变体按强度递增：

| 变体 | 何时用 |
|---|---|
| 单怀疑者 | 发现便宜、量大 |
| 按严重度分档面板（高危 3 个、低危 1 个） | 假"严重"的代价 ≫ 假"低危"的代价 |
| 多数票（3 个独立怀疑者中 2 票） | 发现微妙；单怀疑者噪声大 |
| 全新视角的独立复核 | 生产者**自己也验证过**——自批作业的写作者会放过二评员不会放过的洞 |

### 非对称风险偏置

当错误代价不对称时，"默认反驳"要翻转。死代码怀疑者找*活的证据*并**默认保留**：删掉活代码炸生产，留着死代码只费磁盘。把这种不对称写进提示词——它是工作流的安全属性，要放在模型看得见的地方。

### 逐假设证伪

对竞争性解释（不是独立发现），给每个假设配**一个专职证伪者**，而不是让一个 agent 评估全部——评估五个故事的 agent 会挑偏爱的那个；专职杀死一个故事的 agent 会彻查它。配一个强制每个假设携带*可检验预测*的 schema：那是证伪者的攻击面。

### 证据先行于假设

先用**没有故事要维护**的 agent 收集事实，再从合并的事实生成解释——已经相信"是部署干的"的收集者会用那种眼光读每行日志。不稳定测试同理：嫌疑（便宜扫查）与确认（实证压测）严格分离；诊断只看实证失败。

### 双向事实核查

查"每条主张都有来源"抓编造；查"每个来源都进了主张"抓**遗漏**。发布说明：每行都能追溯到 commit，*且*区间内每个破坏性变更都出现在说明里。方向反过来走，遗漏才看得见。

### 结构性置信

从结果的**形状**在代码里推导置信度，而不是听 agent 自报：唯一假设存活且对手被证伪 = 高；多假设存活 = "分裂"（报告必须说明什么证据能区分）；零存活 = 诚实的 "none"。

## 多样性模式——扇出怎么避免冗余

### Charter 配 Anti-charter

N 个同提示词的并行 agent 产出 N 份相同答案。给每个一个 **charter**（找什么）再配一个 **anti-charter**（忽略什么，因为同伴负责它）。anti-charter 是防止安全评审员拿风格琐事凑数的东西。

### 多模态扫查

一种搜索*角度*找不全时，跑几个彼此盲的视角：死代码——导出分析/入口可达性/陈旧度；不稳定测试——git 历史/code smell/CI 产物；调研——网页/源码/从业者/本地，每个 charter **点明自己的盲区**。跨模态佐证是免费信号：记录并用于排名。

### 身份强制多样性

开放式生成里"给我来点不一样的"照样趋同。给每个生成者一个**哲学身份**（最快上线/可演进/数据优先/故障优先），让它偏置所有决策，并明说*不要*向中庸对冲——评审团需要哲学被表达，不被稀释。

### 评审团

独立评审按固定评分表打**所有**候选，互不可见；代码里计票；从胜者合成同时**嫁接**落选者的最佳点子（让评审即使打低分也指出每个提案最好的一面）。两个细节比看上去重要：评审前**匿名**提案；把**异议**从均值里浮出来而不是平均掉——讨厌胜者的评审通常发现了真弱点。

## 规模模式——大工作怎么保持正确

### 清单分片（可证明的覆盖）

对大语料扇出前，先用一个便宜 agent 建**清单**，把语料切成带明确引用的不相交分片。覆盖变成算术——`已读条目总和 == 总条目数`——而不是一句断言。按清单**在代码里**切片提交列表与条目区间。

### 先校准后分片

分片分类器必须共享词表，否则 A 分片的"同步问题"和 B 分片的"刷新丢数据"落进不同桶，聚合出来是粥。先跨语料样本跑一遍校准固定分类法（含每主题的纳入规则），再把**同一份**词表交给每个分片标注者。"其他"兜底桶 + `emergent` 字段让词表逐轮改进。

### 先侦察后扫描

一个便宜的测绘 agent 让下游专家变得具体：安全侦察（入口、信任边界、秘钥）把六个泛化审计员变成六个*定向*审计员；一次 scope 解析代替五次重复；一份勘察让读取者永不重叠。

### 先线索后深读

便宜发现与昂贵消费分离，中间夹排序：扫查者返回*线索*（引用 + 承诺 + 可信层级），代码去重排序，只有前 N 名被深读——一手来源优先、轶事最后。

### No silent caps

每个上限（`maxDocs`、top-3 修复）都要 `log()` 它丢掉了什么**并写进返回值**。静默截断会被读成"已全覆盖"；列出来的余量是一次针对尾部重跑的邀请。

> dsh 没有 token 预算钩子：规模上限靠轮次/条目数/fleet 大小表达，用户给出预算要求时换算成这些上限，并用 `log()` 汇报进度消耗。

## 分工模式——代码 vs agent

### 判断归 agent，机制归代码

按自然键去重、计票、严重度加权排序、切清单：普通 JavaScript。但当*身份本身*需要阅读——"处理上传失败"和"上传失败时显示重试 UI"是不是同一张票？——合并判断交给 agent。规则：条目有自然键就用代码去重；"相同还是不同"本身是判断就用 agent。

### 提示词专家优于注册专家

通过提示词把*通用*子 agent 特化——charter、anti-charter、身份、不确定时的默认——因为提示词特化随脚本走。dsh 没有 `agentType` 换注册定义的钩子；想要"只读 agent"就在提示词里写只读规则并写进每个提示词，同时把破坏性操作漏斗化到单个阶段。

### 分片不相交是隔离的替代

（dsh 没有 worktree 隔离钩子。）并发改同一批文件的解法是**构造性不相交**：发现阶段把站点分成不相交文件组，再并发编辑——不相交比机器隔离更可靠。分不出不相交组就串行或漏斗化。

### 破坏性操作：漏斗 + 验证

默认只报告（`apply: false`）；执行时删除类操作走**单个顺序 agent**（并行删除者互相漏掉交互——删 A 孤立了 B 的 import），之后全局构建/测试跑一遍。

### 完整性批判 + 有界修复

全新视角的 agent 问"缺了什么？"——其输出是**可执行的修复指令**，不是分数。Top-K 缺口一轮修完就停：批判者永远能找到更多，第二轮的边际产出很少付得起。最强形态：批判者发出*定向狩猎指令*（"官方 changelog v5 里那条版本敏感性声明没有引用"），而不是"多做研究"。

## 组合：会话层串联

dsh 没有 `workflow()` 嵌套钩子，也没有 saved workflow——组合只发生在**会话层**：跑一个工作流，读它的结构化结果，带着判断再发起下一个阶段的调用。这正是深度组合的推荐形态：每个工作流是一个边界清晰的扇出，人在段与段之间保持在环内。

三条规则让串联便宜：

- **结构化返回是组合接口**——消费 `backlog.tickets`、`review.confirmed`，不消费散文。设计工作流时就为被组合而返回可查询对象。
- **像守卫 agent 结果一样守卫段结果**——段会失败或返回空；假设成功的串联者会编造一个。
- **不重审上一段的验证**——评审段的结果到达时已对抗验证过；下一段修补它，不再次判断它。

### Checkpoint 模式（工作流不能提问）

工作流**没有交互原语**——`log()` 是单向的。把未知**返回**为结构化输出（`openQuestions`、`assumptions`、`decisions`），会话层浮出它们，答案作为下一次的 `args` 收回。面对真正产品/设计歧义的工作流都该这么做，而不是让某个 agent 猜——猜才是失败模式。

## 选形状：决策指南

| 任务长相 | 伸手去拿 |
|---|---|
| 评审/审计一个有界产物 | charter 扇出 → 对抗验证 |
| 找全 X，总体未知 | loop-until-dry + 轮换视角 |
| 变更多个站点 | 发现 → 不相交分片 → 单次全局验证 |
| 理解一个大东西 | 勘察 → 并行深读 → 合成 → 批判 |
| 在方案间决策 | 强制多样生成 → 评审团 → 嫁接合成 |
| 解释一个故障 | 证据先行 → 竞争假设 → 证伪者 |
| 消化大语料 | 清单分片 → 校准标注 → 代码聚合 |
| 回答研究问题 | 多模态线索 → 排序深读 → 带引用合成 → 批判轮 |

真实工作流大多组合其中两三个。
